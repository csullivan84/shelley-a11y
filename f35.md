# f35 — 35 exercises to get the hang of Shelley (VaxTui)

Hands-on drills for the coding agent UI. Prefer a throwaway git playground so
you can break things safely.

**Suggested playground**

```bash
mkdir -p /tmp/shelley-lab && cd /tmp/shelley-lab
git init
printf 'package main\n\nfunc main() {\n\tprintln("hi")\n}\n' > main.go
printf 'hello\n' > notes.txt
git add . && git commit -m "lab: start"
# Point a Shelley conversation cwd at this directory.
```

**UI entry points you will use a lot**

- Message composer (Enter send; Shift+Enter newline; `?` for shortcuts help)
- Persistent workspace — Files/History navigator, Monaco editor, and chat together
- Command palette: `Ctrl+K` / `⌘K` — search “Diffs”, “Git Graph”, “Terminal”, “Edit File…”
- Overflow menu (⋯) — Diffs, Git Graph, Terminal, archive, theme, screen reader mode
- Diff viewer — file tree + Monaco (or linear **Text** view under screen readers)
- History — table-based commit index, changed files, and full commit diffs
- Herds — durable terminal groups with explicit focus and bulk open/close controls
- Editable file modal — open a file without waiting for the agent

Mark each exercise done when you can answer the **Check** without guessing.

---

## 1. Boot and pin a working directory

Start Shelley, open a new conversation, set the conversation directory to your
playground (repo root). Send: `pwd && ls`.

**Check:** The agent’s shell runs in that directory; git status is clean.

## 2. First coding turn (bash + patch)

Ask: *Create `greet.go` that exports `Greet(name string) string` returning
`Hello, <name>`, and a table-driven unit test. Run the tests.*

**Check:** New files appear; tool cards for `bash` / `patch` (or equivalent)
show in the transcript; tests pass.

## 3. Open the diff viewer on working tree

`Ctrl+K` → **View Diffs** (or ⋯ → Diffs). Inspect uncommitted files for the
playground.

**Check:** Working tree lists the files from exercise 2; selecting a file shows
old/new content.

## 4. File tree navigation in the diff viewer

In Diffs, walk the tree with keyboard (and VoiceOver if you use it). Open
`greet.go`, then switch to its test file without closing the modal.

**Check:** You can move between files without losing the viewer; focus is
usable.

## 5. Working tree vs a commit

Make a small extra edit (e.g. change a comment), save via agent or Edit File.
In Diffs, switch the range from **working** to a prior commit (commit picker /
range toggle).

**Check:** Working shows the uncommitted delta; a commit range shows only that
commit’s files.

## 6. Linear text diff vs visual Monaco

In Diffs (with a multi-hunk change), toggle **Text** / **Visual** (or rely on
screen-reader mode defaulting to text). Read added/removed lines in linear form.

**Check:** Text mode is navigable as plain content; Visual uses the side-by-side
editor when Monaco has loaded.

## 7. Comment mode on a diff

With a file open in Diffs, stay in **Comment** mode. Select a few lines (or
click a line) and leave a review-style comment.

**Check:** Comment dialog focuses the textarea; submitting inserts a quotable
snippet you can send back into chat as instructions.

## 8. Edit mode in the diff viewer

Switch Diffs to **Edit** mode on a working-tree file. Fix a typo, wait for
auto-save (status should leave “saving”). Reload the file from disk / re-open.

**Check:** Edit mode is only writable for working-tree views; save status
returns to idle/saved; disk matches what you typed.

## 9. Edit File… without the agent

`Ctrl+K` / overflow path → **Edit File…**. Open `notes.txt`, append a line,
save/close. Confirm with Diffs or `git diff`.

**Check:** You can edit outside an agent turn; the change shows in working tree
diffs.

## 10. Git graph: orient yourself

Open **Git Graph**. Move with Up/Down among commits. Note branch tips and the
stack relative to the merge-base / working state.

**Check:** You can identify HEAD and the lab’s recent commits without leaving
the UI.

## 11. Git graph → open a commit’s diff

From the graph, open an older commit’s diff (commit actions above the message
body). Review files for that SHA only.

**Check:** Diff viewer lands on that commit’s file set, not the full working
tree mess.

## 12. Ask the agent to commit

In chat: *Stage the greet package and commit with a clear message. Do not push.*

Open Diffs and the graph again.

**Check:** Working tree is clean (or only leftover notes edits); graph shows the
new commit; agent used shell/git tools rather than inventing status.

## 13. Multi-file refactor through the agent

Prompt: *Rename `Greet` to `Hello`, update call sites and tests, run tests.*

While it runs, expand tool cards; after, open Diffs and walk every touched file.

**Check:** You can reconcile transcript tool patches with the unified working
diff; tests still pass.

## 14. Stop mid-flight

Start a longer task (*Add a CLI flag, help text, and integration test…*). Hit
**Stop** while tools are running. Optionally send a follow-up that pivots.

**Check:** Status returns to idle; cancelled tool / “Operation cancelled”
appears as appropriate; a new turn can continue from the partial tree.

## 15. Queue messages while working

With the agent busy (or after Stop, start a long turn), queue a second message
before the first finishes. Cancel-all queued if the UI offers it.

**Check:** You understand when messages enqueue vs send immediately; cancel-all
clears the queue without mystery leftovers.

## 16. Subagent (delegated work)

Ask for parallel exploration: *Use a subagent to list packages that import
`testing` under this repo; summarize only.* (On a larger codebase if the lab is
too small.)

**Check:** A subagent conversation appears / tool card links to it; parent gets
a completion summary; cancelling parent can cascade (try once deliberately).

## 17. Keyword search / codebase find

On a real project cwd (e.g. this Shelley tree): *Find where the git file-diff
API is implemented and summarize the handler.* Prefer tools over guessing.

**Check:** Agent uses search/read tools; answer cites real paths; you can open
those paths in Edit File or Diffs after a local edit.

## 18. Patch tool fidelity

Make a deliberate bad request: *Change the public API of greet without updating
tests.* After failure or red tests, say *Fix tests only.*

Open Diffs between the broken and fixed states (working vs last good commit).

**Check:** You can read a failing test run in the tool output, then verify the
fix hunks are minimal.

## 19. Terminal panel (you drive the shell)

`Ctrl+K` → **Open Terminal**. Run `git status`, `git log -3 --oneline`, a quick
`go test` (or language of the lab). Compare with asking the agent the same.

**Check:** Terminal is interactive for you; agent chat remains separate; cwd
matches the conversation when expected.

## 20. Worktree isolation

From palette: **New Conversation in New Worktree** (or create worktree, then
new chat in that path). In the worktree chat, make a divergent edit and commit.

**Check:** Main worktree is untouched; graph/diffs in each conversation see
their own cwd; no cross-contamination.

## 21. Context pressure: long coding session

In one conversation, do several refactors until the context bar climbs. Use
distill / new generation (compact) from the UI when offered. Continue with a
small follow-up task.

**Check:** After compact, the agent still knows the cwd and recent goal well
enough to keep working; you can still open Diffs on the real tree.

## 22. Model switch mid-project

Start a task on model A (e.g. cheap/fast). After a commit, switch models and
ask for a review of `git diff HEAD~1`.

**Check:** Model change is visible in the transcript; review matches the real
diff; health/latency hints (if shown) update.

## 23. Retry and error surfaces

Force a recoverable failure if you can (bad model key on a custom model, or
cancel network). Use **Retry** when the latest message is a retryable error.
Also try a non-retryable mistake and confirm Retry stays hidden.

**Check:** Retry re-runs without inventing a fake user message; errors are
announced/alerted in the status area.

## 24. Export / archive / resume navigation

Export the conversation. Archive it. Find it under archived, unarchive, jump
between user messages (`Ctrl+M, N` / `P` or palette). Rename the conversation to
something searchable.

**Check:** History survives archive; palette search finds the rename; export is
readable offline.

## 25. End-to-end “ship a tiny change”

In the playground (or a real branch you own):

1. New conversation at the right cwd (or worktree).
2. Implement a small, testable feature via the agent.
3. Watch tools; Stop once if something goes sideways; continue.
4. Open **Diffs** — Text + Visual; leave one comment for yourself; apply any
   last edit in Edit mode or Edit File.
5. Open **Git Graph** — confirm stack.
6. Have the agent commit (no push unless you intend it).
7. Optional: open Terminal and `git show --stat HEAD`.

**Check:** You used agent + Diffs + Graph + (optional) Terminal as one loop,
not only chat. You could explain the final diff to someone else from the UI
alone.

## 26. Start fresh at the root and choose a directory

Open Shelley at `/` rather than a saved `/c/<slug>` URL. Confirm that the
workspace starts with a fresh query instead of silently reopening the most
recent conversation. Use the directory button above **Files** to select the
playground.

**Check:** The workspace changes to the selected directory and starts a new
conversation there; an old conversation opens only when you explicitly choose
it from the drawer or visit its URL.

## 27. Use the persistent three-pane workspace

In **Files**, filter for `greet`, open `greet.go` and its test, then move among
the Files, Code, and Chat panes (the layout becomes tabs on a narrow screen).
Make one file dirty and watch its Git status indicator in the navigator after
saving and refreshing.

**Check:** File navigation, Monaco, and chat share one cwd; multiple files stay
open as editor tabs; status letters identify added or modified files that are
still present in the tree.

## 28. Verify editor autosave and reload persistence

Edit `notes.txt` in the workspace editor and wait for **Saved**. Put the cursor
well below the first line, switch to another editor tab and back, then reload
Shelley.

**Check:** The disk contains the edit; the tab set and active file return for
that cwd after reload; switching tabs before reload restores the editor
position. A different cwd keeps a separate tab set.

## 29. Send a precise selection with Ask Shelley

Select several lines in the workspace editor and press **Ask Shelley**. Inspect
the composer before sending, add a concrete request such as *extract this into
a helper*, then submit it.

**Check:** The draft contains a relative `file#Lx-Ly` reference plus the
selected text; the response and patch address those lines without you manually
copying the filename or range.

## 30. Browse the table-based History index

Open the workspace **History** tab. Move through commit rows by hash and
message, select one, inspect its file list and addition/deletion counts, and
open the file's current working copy. Choose **Open full diff**, then select the
same SHA as the diff range.

**Check:** You can jump directly among non-adjacent commits from the table
instead of stepping through Previous/Next; the selected row and file detail
match the commit you inspect in Diffs.

## 31. Jump from a patch tool to the workspace editor

Ask Shelley for a small edit that produces a patch tool card. In the completed
card, activate the filename rather than opening the standalone diff viewer.

**Check:** The patched file opens as a tab in the persistent workspace editor
at the conversation cwd; the patch card remains in the transcript and no path
has to be re-entered.

## 32. Exercise onboarding and provider handoff safely

Build Shelley and start a separate instance with a throwaway database, for
example:

```bash
./bin/shelley --db /tmp/shelley-f35-onboarding.db serve -port 8002
```

Open that instance. Review any credentials discovered from Hermes or OpenCode
(including imported OpenAI or xAI OAuth entries), or use an OpenRouter key.
Complete onboarding, then open **Manage Models** and use **Providers** to return
to provider setup.

**Check:** The first page exposes provider metadata but never secret values;
selected credentials create usable models in the temporary instance; Providers
and Manage Models lead back and forth without another special “ask Grok” flow.

## 33. Test response-finished browser notifications

Open **Notifications**. Enable browser notifications, send its **Test**
notification, and enable the favicon badge. Start a real Shelley request, move
to another tab while it runs, and wait for the turn to finish. Also inspect the
quiet-hours control so you know why a future notification might be muted.

**Check:** Permission is requested through the browser UI; the test arrives;
an end-of-turn event produces a notification while Shelley is in the
background; the favicon is ghosted while work is active and returns to ready
when the response finishes.

## 34. Build and focus a durable herd

Open **Herds** from the command palette. Create a herd with the playground as
its default cwd and a harmless long-running default command. Add a new terminal
and one existing loose terminal, link one member to a conversation, then use
**Focus terminal** explicitly.

**Check:** Members retain their command/cwd recipes; selecting a member does
not attach its PTY until Focus; the linked conversation opens from the member;
detaching a running member does not restart or kill its process.

## 35. Drive herd lifecycle and bulk controls

In the herd, use **Close all** and read the confirmation, especially any
working/needs-you warnings. Reopen with **Open all**, close one member, reopen
it from its saved recipe, then rename, archive, and restore the herd. If a
recipe is deliberately invalid, use **Repair recipe** and retry.

**Check:** Bulk results report individual failures instead of hiding them;
open/closed/missing and working/needs-you filters match reality; archive keeps
the herd definition and member recipes after the terminals are closed; restore
and repaired recipes work without recreating the herd.

## Stretch (optional)

- **A11y pass:** Overflow → Screen reader mode On; redo exercises 3–8 with VO.
  Confirm thinking/tool bodies stay reachable when collapsed; status announces
  working/idle.
- **Browser tool:** Ask the agent to open a local `index.html` it created and
  screenshot or assert text (needs browser tooling enabled).
- **Hooks:** Skim `HOOKS.md` and add a no-op slash hook; invoke it from chat.
- **Predictable-only:** `./bin/shelley -predictable-only serve …` and practice
  UI flows without burning tokens (scripted model).
